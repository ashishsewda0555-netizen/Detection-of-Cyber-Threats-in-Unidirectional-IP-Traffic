# Netizen Threat Intelligence ML Pipeline
**Final Project Documentation**

---

## 1. Executive Summary

This project implements a high-throughput, **Dual-Pipeline Machine Learning Intrusion Detection System (IDS)** designed specifically to intercept Zero-Day Distributed Denial of Service (DDoS) attacks, stealthy port scans, and data exfiltration attempts. 

By combining the high-frequency packet heuristics of **Scapy** with the deep flow state-tracking of **Zeek**, the system leverages a hybridized ML engine (Isolation Forest + Regularized Random Forest) to evaluate network flows in real-time, delivering highly accurate, interpretable threat intelligence to a React-based SOC dashboard.

---

## 2. The Dual-Pipeline Architecture

To circumvent the traditional limitations of single-stream packet sniffers (which drop packets under volumetric load) and flow aggregators (which lose high-frequency TCP flag sequences), the data ingestion layer is split into two asynchronous paths:

### A. The Scapy Fast-Path (High-Frequency Metrics)
- **Engine:** BPF-filtered Scapy packet capture.
- **Purpose:** Extracts micro-second TCP flag anomalies and rate metrics critical for detecting volumetric attacks (e.g., SYN Floods, UDP Floods) where flow state is irrelevant or purposefully broken.
- **Features Extracted:** `flow_rate`, `packet_rate`, `syn_flag_sum`, `ack_flag_sum`, `syn_ack_ratio`, `packet_size_std`, `unique_src_count`.

### B. The Zeek Flow-Path (Deep Metadata)
- **Engine:** Zeek Network Security Monitor (`conn.log`).
- **Purpose:** Tracks prolonged session metadata, byte transfers, and established connections necessary for identifying slow-and-low application-layer attacks and data exfiltration.
- **Features Extracted:** `orig_bytes`, `resp_bytes`, `exfiltration_ratio` (calculated as `orig_bytes / (resp_bytes + 1)`).

### Asynchronous Synthesis Layer
The two streams are asynchronously synthesized in memory, generating a unified 14-feature matrix per flow before being handed to the ML inference engine, guaranteeing zero packet drops during DDoS conditions.

---

## 3. The Dual-Engine Machine Learning Core

The ML backend (`scorer.py`, `train_unified_model.py`) executes a two-stage evaluation pipeline to guarantee both high recall against known attacks and zero-day anomaly detection.

### Stage 1: The Zero-Day Anomaly Engine (Isolation Forest)
- **Model:** `sklearn.ensemble.IsolationForest`
- **Training:** Trained exclusively on benign network traffic with a 5% contamination bound.
- **Function:** Establishes a baseline of "normal" network physics. If a flow heavily deviates (measured via raw Z-scores), it is flagged as an anomaly (`ddos_unknown_variant`). This protects the network from novel, unclassified attack vectors.

### Stage 2: The Signature Classification Engine (Random Forest)
- **Model:** `sklearn.ensemble.RandomForestClassifier`
- **Training:** Trained on a heavily augmented, regularized schema encompassing: `benign`, `ddos_spoofed_syn_flood`, and `port_scan`.
- **Regularization (`max_depth=15`):** To prevent severe overfitting (alert fatigue), the Random Forest trees are strictly bounded. This forces the model to learn the underlying mathematical physics of an attack (e.g., the relationship between `syn_ack_ratio` and `flow_rate`) rather than memorizing hardcoded byte counts.

### Inference Calibration & Thresholding
- **Strict Confidence Gating:** The pipeline discards the standard 50% probability boundary. A threat is only escalated to a **`critical`** alert if the model's confidence exceeds **`0.85 (85%)`**.
- **Alert Suppression:** Classifications falling between `0.50` and `0.85` are dynamically downgraded to a `warning`, drastically reducing false-positive alert fatigue for the SOC team during high-throughput (10,000+ flows/sec) environments.

---

## 4. Feature Interpretability (SHAP)

Machine learning in a SOC environment requires explainability. Every critical alert generated by the pipeline is passed through a SHAP (SHapley Additive exPlanations) `TreeExplainer`. 

This mathematical framework calculates the exact directional contribution of every feature toward the model's final decision. The SHAP values are streamed to the frontend via Server-Sent Events (SSE).

---

## 5. React Dashboard UI (Threat Intelligence Center)

The frontend (`Home.tsx`) is a React-Vite application that consumes the SSE stream from the FastAPI backend, rendering a live, low-latency threat intelligence dashboard.

### The Verdict Inspector (Evidence Grid)
When an attack is intercepted, the UI renders the SHAP explanations into an Evidence Grid, explicitly bridging the visual output back to the Dual-Pipeline architecture:
- **`[SCAPY FAST-PATH]` Tag:** Displayed next to high-frequency metrics (e.g., `SYN_ACK_RATIO`).
- **`[ZEEK FLOW-PATH]` Tag:** Displayed next to volumetric metadata (e.g., `EXFILTRATION_RATIO`).
- **Color Coding:** Malicious contributing metrics (positive SHAP values) are highlighted in red, while mitigating factors are highlighted in green, instantly explaining *why* the ML model intercepted the flow.

---

## 6. Performance & Evaluation (Holdout Validation)

To prove operational readiness and defeat synthetic overfitting, the finalized model was evaluated against a highly erratic holdout dataset simulating raw CIC-DDoS2019 traffic. 

- **Holdout Specifications:** Injected with up to 40% multiplicative variance (simulating extreme packet drops, network jitter, and overlapping benign/attack signatures).
- **Results:** The regularized dual-engine model successfully maintained an operational baseline of **~0.96 macro average F1-Score**.
- **Conclusion:** The feature engineering successfully extracts the differentiating physics of DDoS attacks without succumbing to the brittle memorization that causes legacy ML IDS systems to fail in production.

## 7. Future Scope & Scalability Roadmap

1. **JA4/JA4S TLS Fingerprinting:** Integration of JA4 hashes into the Zeek flow-path to identify behavioral consistencies in malicious botnet client handshakes, regardless of IP spoofing or payload encryption.
2. **Scalar DGA Detection:** Extracting mathematical properties (Vowel-to-Consonant Ratio, Hex Density, Shannon Entropy) from DNS queries to detect Domain Generation Algorithms without relying on memory-intensive TF-IDF vectorizers.
3. **Kafka Integration:** Shifting the asynchronous synthesis layer (`merge_pipelines.py`) into Apache Kafka for horizontal, multi-node scaling across enterprise environments.
